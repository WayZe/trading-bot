# Дизайн учебного торгового бота (Bybit, спот, свинг)

- Дата: 2026-09-05
- Статус: утверждено (этапы 0–1 реализованы)
- Область этого документа: общий дизайн системы; детали этапов 2+ будут уточняться по мере реализации.

## 1. Цели и рамки

**Цель.** Научиться алготрейдингу на реальном рынке с прицелом на live-торговлю позже.
Проект сознательно идёт по пути «backtest first»: сначала честный бэктестер, потом
paper-трейдинг на testnet, и только затем — live малой суммой.

- **Рынок:** криптовалюты, биржа Bybit, спот.
- **Стиль торговли:** свинг-стратегии на свечах; таймфреймы M15–D1 (основной — 4h).
- **MVP:** бэктестер + простая стратегия SMA-кросс + отчёты с метриками и графиками.
- **Ограничения MVP:** long-only, максимум одна позиция одновременно, один символ.

## 2. Ключевой принцип: стратегия — плагин

Стратегия не знает, кто её вызывает — бэктест или будущий live-движок. Контракт один:

- Стратегия получает свечу за свечёй (event-driven) через `on_candle(...)`.
- Стратегия возвращает/выставляет торговые намерения (например, «войти в лонг»,
  «закрыть позицию»), а не исполняет их сама.
- Исполнением управляет движок через брокера (эмуляция в бэктесте, реальный API в live).

Это позволяет: писать стратегии без бэктест-специфичного кода, тестировать одну и ту же
стратегию на истории и на live-потоке, добавлять новые стратегии как отдельные модули.

## 3. Архитектура

```
data                → indicators        → strategy           → engine              → report
exchange.py         sma.py                base.py              backtest.py           metrics.py
downloader.py       ema.py                sma_cross.py         broker.py             plots.py
storage.py          rsi.py                                     portfolio.py
                    atr.py                                     risk.py
```

- **data** — работа с биржей и хранилищем:
  - `exchange.py` — тонкая обёртка над ccxt (`ccxt.bybit`), публичный API OHLCV,
    ключи не нужны; rate limit на стороне ccxt (`enableRateLimit`).
  - `downloader.py` — пагинационная загрузка истории с retry/backoff, инкрементальное
    обновление, доливка гэпов, валидация.
  - `storage.py` — Parquet-хранилище через pandas; путь `data/{exchange}/{SYMBOL_SLUG}/{tf}.parquet`
    (slug: `BTC/USDT → BTC_USDT`); атомарная запись (tmp + rename).
- **indicators** — индикаторы пишем сами (без ta-lib и аналогов): SMA, EMA, RSI, ATR.
  Причины: обучение, контроль над NaN-семантикой на границах окна, отсутствие нативных зависимостей.
- **strategy** — `base.py` (абстрактный контракт `on_candle`) + конкретные стратегии
  (первая — `sma_cross`: вход при пересечении быстрой SMA медленной снизу вверх, выход при обратном).
- **engine** — бэктест-движок:
  - `backtest.py` — основной цикл: свеча за свечёй, сигнал → исполнение.
  - `broker.py` — эмуляция исполнения ордеров (комиссии, проскальзывание).
  - `portfolio.py` — учёт позиций, кэша, equity.
  - `risk.py` — ограничения риска (размер позиции, stop-loss и т.п.).
- **report** — метрики (total return, CAGR, Sharpe, max drawdown, win rate, …) и графики
  (equity curve, drawdown, сделки на цене) через matplotlib.
- **CLI** — typer-приложение `trading-bot` с командами `download`, `backtest`, `report`.

## 4. Схема данных

OHLCV-свечи хранятся в Parquet, одна строка — одна свеча:

| Колонка     | Тип                    |
|-------------|------------------------|
| `timestamp` | `datetime64[ms, UTC]`  |
| `open`      | `float64`              |
| `high`      | `float64`              |
| `low`       | `float64`              |
| `close`     | `float64`              |
| `volume`    | `float64`              |

Инварианты: отсортировано по `timestamp`, без дублей, таймфрейм регулярный
(гэпы — аномалия, о которой загрузчик обязан сообщить и попытаться долить).

Таймфреймы в формате ccxt: `'15m'`, `'1h'`, `'4h'`, `'1d'`.

## 5. Честность бэктеста

- Сигнал вычисляется по **закрытой** свече; исполнение — по **open следующей** свечи.
- Издержки учитываются явно: комиссия taker 0.1% по умолчанию (настраивается),
  проскальзывание в базисных пунктах (по умолчанию 5 bps).
- **Стоп-лосс/тейк-профит принадлежит движку, а не стратегии.** Стратегия
  задаёт дистанцию стопа от close сигнальной свечи (`close − atr_mult·ATR`);
  интрабарный стоп движка якорится к фактической цене исполнения: заданная
  дистанция переносится на fill-цену (`active_stop = fill − дистанция`,
  симметрично для тейка). Проверка внутри свечи (`low ≤ stop`, нестрого);
  гэп через уровень исполняется по open (консервативно), при одновременном
  касании стопа и тейка приоритет у стопа. Неположительная дистанция после
  пересчёта отключает уровень.
- Движок валидирует входной датасет: пустые данные, отсутствие обязательных
  колонок, NaN в них или нарушение `high ≥ low` — явный `ValueError`
  (NaN не должен тихо отравлять прогон).
- Никакого заглядывания в будущее: на момент решения доступны только свечи до текущей включительно.
- Long-only, одна позиция — в MVP; шорт и пирамидинг — после live-этапа, если понадобятся.

## 6. Обработка ошибок и надёжность

- Сетевые запросы к бирже: retry до 6 попыток с экспоненциальным backoff
  (1s → 2s → 4s → 8s → 16s) на `ccxt.NetworkError` (включая наследника
  `ccxt.RateLimitExceeded`).
- В датасет попадают только **закрытые** свечи: свеча закрыта ⟺
  `timestamp + timeframe_ms ≤ now`. Формирующаяся последняя свеча
  отбрасывается и в `download`, и в `update` (в update последняя свеча
  перезабирается, но незакрытый хвост не сохраняется).
- Валидация каждого датасета (`validate_ohlcv`): `high >= max(open, close)`,
  `low <= min(open, close)`, `volume >= 0`, нет NaN, таймстемпы уникальны и монотонны.
- Детект гэпов: интервалы между свечами должны соответствовать таймфрейму;
  пропущенные диапазоны доливаются отдельными запросами, затем датасет
  валидируется повторно. Если проблемы остаются — загрузка падает с `ValueError`
  и перечнем проблем (лучше явная ошибка, чем тихо дырявые данные); то же
  правило действует после инкрементального `update`.

## 7. Конфигурация

YAML-конфиги в `config/` (пример — `config/backtest.yaml`), парсинг в pydantic-модели
(`BacktestConfig`): символ, таймфрейм, период, комиссия, проскальзывание, размер позиции,
имя стратегии и её параметры. Pydantic даёт валидацию типов и понятные ошибки.

## 8. Роадмап после MVP

1. **Testnet paper-трейдинг** — тот же контракт стратегии, но исполнение через
   Bybit testnet API; сверка поведения с бэктестом.
2. **Live малой суммой** — мониторинг состояния, уведомления в Telegram,
   kill-switch (остановка по anomalию/просадке/вмешательству человека).
3. **Walk-forward оптимизация** — подбор параметров стратегии без переобучения
   на всей истории; rolling-окна train/test.

## 9. Технологии

- Python 3.12+, uv (менеджер зависимостей), src-лейаут `src/trading_bot/`.
- ccxt (Bybit, публичный OHLCV), pandas + pyarrow (Parquet), pydantic (конфиги),
  pyyaml, typer (CLI), matplotlib (отчёты).
- Тесты: pytest + pytest-mock, все офлайн (ccxt мокается). Линтер: ruff.
